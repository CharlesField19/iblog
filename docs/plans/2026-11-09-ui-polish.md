# iBlog UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use subagent-driven-development (recommended) or execute it inline in this session, task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Improve the existing Vue public UI without changing its visual direction: keep the home hero clean, keep article tags on one horizontally scrollable row, improve code readability, stabilize the home subtitle, and progressively enhance selected corners.

**Architecture:** Keep Go SSR, Vue 3, Tailwind CSS and SQLite unchanged. Home article content remains in the document after the first viewport; tag filtering remains the existing query-based interaction; syntax highlighting is performed by the existing Go Markdown renderer so SSR and admin preview share the same HTML.

**Tech Stack:** Go, goldmark, goldmark-highlighting, Vue 3, Tailwind CSS, vue-i18n.

**Spec:** Existing UI feasibility report agreed in conversation on 2026-11-09.

## Global Constraints

- Do not migrate to React, Next.js, or add a frontend component library.
- Preserve current light/dark theme tokens and accessibility behavior.
- Do not remove home article content; place it below the first viewport.
- Keep tags in one horizontal scroll row; do not add a “more” menu yet.
- Preserve Markdown preview and published HTML parity.
- Long code lines must wrap inside the code block without forcing page-wide horizontal scrolling.

## Review Focus

- A narrow phone viewport must keep the home hero as the first screen and allow the article section to be reached by scrolling.
- A large number of tags must remain one row and remain keyboard accessible.
- Code without a language must still render safely and readably.
- Existing unsafe Markdown must remain sanitized after the highlighting extension is enabled.
- Safari/Firefox without `corner-shape` must retain normal rounded corners.
